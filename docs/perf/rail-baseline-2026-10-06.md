## Findings

- **Rail calls per search: 3.7 cold, 0.3 warm.** Cold: 11 calls for 3 routes. Warm: 1 call, a 91% saving.
  - Tier 2 (saved timetables) saved **8** calls, one per timetable lookup.
  - Tier 1 saved **2**: one pair known to be empty (Delhi Hazrat Nizamuddin → Jaipur on Saturdays) and one search that
    went straight to the station pair that worked (Gurugram → Agra).
- **Estimated cost saved.**
  - **RailRadar (free tier, 1,000 requests a month).**
    - At about 3.7 calls per new route, the tier covers about 270 new routes a month.
    - A repeat of a route already saved costs about 0 calls for up to 45 days. Before Phase 2 it cost about 3.7 calls
      once the 14-day/12-hour caches had lapsed.
    - Saving per repeat: about 3.4 calls, or about 0.34% of the monthly free tier.
    - No paid RailRadar price is in the price table, so there is no dollar figure. Give me the plan price and I'll add
      it to `TELEMETRY_PRICES`.
  - **Google.** Phase 2 doesn't change Google calls, which were about $0.22–0.35 per cold full plan in Phase 0.
- **The one warm call was wasted.**
  - It was IRCTC1's station search for Mussoorie, and it failed: *IRCTC1's monthly quota is used up* ("exceeded the
    MONTHLY quota for Basic").
  - IRCTC1 may not store anything (I7), so this failing call repeats on every Mussoorie search.
  - Mussoorie's railhead is already known (Dehradun, `NEARBY_HUBS`), so the call isn't needed.
  - Fix: Phase 4's provider gateway with a circuit breaker. A smaller fix now: skip the live station search when the
    built-in hub list already covers the place.
- **Delhi → Jaipur showed 20 trains cold and 19 warm.**
  - The missing train is numbered `150131`, six digits. Validation keeps only 4–5 digit numbers, so it was dropped
    from the saved copy.
  - Live answers aren't validated before they're shown, so the same route shows different trains depending on whether
    it was cached.
  - Two options: validate live answers with the same rules, or allow 6-digit numbers if RailRadar uses them for real
    services.
- **Not covered:**
  - Google calls and the full planner (the 30-call cap rules out even one cold full plan);
  - the stale or aging refresh path (the copies were minutes old);
  - connection searches with a change of train (none of these routes needed one).
